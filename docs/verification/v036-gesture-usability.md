# v0.3.6 손동작과 처리 지연 검증

사용자는 전체 기능을 사용한 뒤 이동의 매끄러움과 다른 동작의 조작 난이도를 보고했다. 원본은 다운로드 폴더의 v0.3.5 세션 기록으로, 손 좌표와 영상은 Git에 저장하지 않았다. [집계](v036-user-summary.json)만 보존한다.

## 관측과 재현

- 4,465개 수신 프레임, 유효 손 3,593개, 오래되어 제외된 프레임 132개. 마지막 `isRunning=true`로 이번 기록에서는 카메라·제어 전체 종료가 확인되지 않았다.
- 스크롤 도중 불명확한 손 모양 한 프레임이 즉시 suspended로 전환시켰다. 이후 V 자세로 돌아왔지만 검지 한 개만 재활성화할 수 있어 스크롤이 재개되지 않았다.
- GestureUsabilityTests의 기존 동작 재현: 두 손가락 재개, 잠깐 불명확해진 스크롤, 67ms 클릭, 두 번째 클릭 위치 유지가 실패했다. [수정 전 로그](v036-gesture-red.log).
- 수정은 기본 comfortable 모드에 적용했다. 기존 direct 모드의 손동작 시간 조건은 유지한다. 버튼 해제, 오래된 영상 거부, 열린 손바닥의 즉시 정지는 유지한다.

## 대기열과 화면 갱신

기존 결과 전달 방식과 같은 1:1 큐 전달을 재현한 단위 테스트에서는 소비자가 바쁠 때 제출한 100개 결과가 모두 쌓였다. LatestValueDelivery는 최신 결과 하나로 대체하고, 처리 중 도착한 결과도 잃지 않고 다음 번에 전달한다. 카메라 onResult가 이 전달기를 사용한다. 순서·세션·촬영 시각 검사는 기존 입력 엔진이 수행한다.

입력 엔진과 진단 화면의 알림을 분리했다. 입력은 받은 결과마다 처리하고, 손 좌표·진단 수치 표시는 20Hz로 갱신한다. 사용자 설정·시작/정지 상태 변경은 기존 SwiftUI 알림을 사용한다.

## 내장 카메라 측정

같은 설치 경로의 앱을 버전별로 10초씩 실행해 카메라와 Vision의 시간만 기록했다. OS 입력은 꺼져 있다. 두 실행의 손 인식 상태가 달랐으며 통제된 손 움직임 비교가 아니다.

| 측정 | v0.3.5 | v0.3.6 |
| --- | ---: | ---: |
| 표본 프레임 | 191 | 169 |
| 카메라 → 수신 중앙값 | 86.8 ms | 109.3 ms |
| 카메라 → 수신 p95 | 117.7 ms | 121.8 ms |
| Vision → 메인 큐 중앙값 | 0.05 ms | 0.07 ms |
| Vision → 메인 큐 p95 | 5.7 ms | 6.9 ms |

[이전 측정](v036-camera-before.json), [새 측정](v036-camera-after.json). 새 측정에서 교체된 대기 결과는 0개였다. 이 짧은 측정은 실제 연결과 연속 실행을 확인하며, 지연 감소나 사용자 체감 개선을 입증하지 않는다. 사용자 원본의 카메라→수신 중앙값은 107.8ms, p95는 166.6ms였다.

## 테스트와 설치

- [전체 테스트](v036-tests.log): 74개 발견, 73개 통과, v0.3.3 전용 원본 재생 1개 건너뜀. 최신 v0.3.5 원본 재생은 실행했다. 원본 경로 환경변수 없이 실행하면 두 원본 재생 테스트가 건너뛰어진다.
- 설치본 v0.3.6 build 9. 기존 번들 ID와 개발 인증서 유지. [설치 로그](v036-install.log).
- 최종 설치 상태와 합성 재생은 별도 JSON으로 보존한다. 합성 재생은 실제 OS 입력을 보내지 않는다.
- 실제 손으로 새 버전의 클릭·드래그·우클릭을 끝까지 검증한 결과는 아직 없다. 우클릭 동작 변경에 대한 사용자 답변이 없어 현재 엄지·중지 방식을 유지했다.
