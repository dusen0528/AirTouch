# v0.4.0 개인 보정과 조작 부담 개선

2026-09-17. 설치 경로 `~/Applications/AirTouch.app`, 앱 ID `dev.airtouch.mac` 유지.

## 적용 범위

사용자가 선택한 개인 보정, 드래그 잠금, 커서 옆 상태 표시를 구현했다. 추가 조작 팔레트는 포함하지 않는다.

- **개인 보정:** 정지 4초, 좌우 7초, 상하 7초, 집기 3회를 최소 6초 관측한다. 유효한 관측 시간만 합산한다. 신뢰도가 낮거나 늦은 프레임, 부족한 움직임, 구분되지 않는 집기는 적용하지 않고 재시작을 안내한다. 결과 확인 후 적용하며 설정에서 재보정·초기화한다. 프로필에는 제한 범위 안의 감도·필터·집기·드래그 기준과 집계값만 저장한다. 보정 프레임은 일반 손 좌표 진단 기록에 포함하지 않는다.
- **드래그 잠금:** 집은 상태로 움직여 끌기를 시작하고 손가락을 풀면 버튼을 유지한다. 다시 집는 동작을 100ms 이상 확인하면 놓고, 손가락을 펼칠 때까지 재클릭을 막는다. 한 프레임 접촉은 무시한다. 손 상실·펼친 손·중지·영상 만료 시 버튼을 해제한다. 설정에서 계속 집는 기존 방식으로 전환할 수 있다.
- **커서 상태:** 실제 커서 근처의 AppKit 패널이 준비·이동·클릭·끌기 잠금·놓기 완료·손 상실·마우스 양보를 표시한다. 클릭을 통과시키며 키 창이나 주 창이 되지 않는다. 중지·표시 끄기 시 숨긴다.
- **처리 경로:** 실제 제어는 Vision → 최신 프레임 하나 → 별도 입력 판정 큐 → 기존 최종 출력 큐 순서다. UI는 별도의 최신 스냅샷을 받는다. UI가 지연돼도 입력 판정과 버튼 해제 watchdog은 기다리지 않는다. 물리 마우스 양보·중지·세대 변경은 동기적으로 차단해 이전 대기 프레임의 재입력을 막는다. 입력 요청 시각은 OS 전송·대상 앱 처리·화면 표시 완료 시각이 아니다.

## Apple 문서와 카메라 설정

[Apple TN2445](https://developer.apple.com/library/archive/technotes/tn2445/_index.html)에 따라 출력의 늦은 프레임 폐기를 유지하고 드롭 사유별 콜백을 센다. discontinuity는 손실 프레임 수가 알려지지 않으므로 콜백 수를 프레임 수로 부풀리지 않는다.

[Apple TN3121](https://developer.apple.com/documentation/technotes/tn3121-selecting-a-pixel-format-for-an-avcapturevideodataoutput)에 따라 native YCbCr 420v를 유지한다. Vision의 Objective-C 임시 객체 수명을 프레임별 autoreleasepool로 제한했다. 이 두 설정만으로 특정 지연 개선량이 보장되지는 않는다.

preset 이름만으로 실제 카메라 해상도를 판단하면 안 된다는 문제가 실측에서 드러났다. 720p와 480p 요청 모두 1920×1080 버퍼였다. 입력 연결 전 canSetSessionPreset이 false인 가설은 구성만 조사해 기각했다. activeFormat을 직접 지정해도 설정 잠금을 풀고 시작하면 1080p로 돌아왔다. [Apple Formats](https://developer.apple.com/documentation/avfoundation/capture-device-formats)와 [lockForConfiguration](https://developer.apple.com/documentation/avfoundation/avcapturedevice/lockforconfiguration())은 macOS에서 고정 형식을 유지할 때 잠금을 유지해야 한다고 설명한다. 최종 실수신 크기와 측정값은 아래에 별도로 기록한다.

내장 카메라만 선택하도록 macOS 14의 Continuity Camera 장치 유형 구분에 명시적으로 참여한다. 설치 SDK `AVCaptureDevice.h`에 따르면 해당 Info.plist 키가 없으면 Continuity Camera도 builtInWideAngleCamera로 보고될 수 있다. 새로운 카메라 권한이나 별도 번들 ID를 만들지 않는다.

기본 해상도 후보는 720p, 480p는 개발 측정 옵션이다. preview-sized buffer API는 현재 macOS SDK에서 사용 불가여서 적용하지 않았다. 두 손 감지 시 입력 중단은 유지한다. 현재 카메라 최대 30fps이며 근거 없는 60fps 전환이나 예측 좌표로 지연 전체를 숨기는 방식을 넣지 않았다.

## 자동 검증

자동 테스트 117개 통과, 제공되지 않은 v0.3.3 원본 전용 재생 1개를 건너뛰었다. 현재 v0.3.5 기록 재생의 스크롤 재개 확인은 9/9로 유지됐다. [전체 테스트 로그](v040-tests.log), [Release 설치 로그](v040-install.log).

검증 범위는 다음과 같다.

- 개인 보정의 낮은 신뢰도·중복·손 상실·움직임 부족·집기 구분·적용값 범위, 저장/복원/초기화.
- 끌기 잠금 이동·한 프레임 접촉·놓기·중지/손 상실 해제, 잠금 켜짐/꺼짐 데모.
- 실제 SystemTrackingController를 가짜 출력 sink와 실행해 UI 정체가 입력을 막지 않는지, 중지/양보/세대 변경 뒤 이전 작업이 차단되는지 확인. 이 시험은 OS 마우스 이벤트를 전송하지 않는다.
- 숨겨진 NSHostingView로 실제 CalibrationView의 시작·진행·완료 상태를 렌더링해 한글·버튼·진행률 배치를 직접 확인했다. 데스크톱 캡처나 카메라 영상이 아니며 진행 화면의 카메라는 OFF 합성 상태다.
- CursorStatusOverlay의 키/주 창 금지, 클릭 통과, 손 상실/마우스 양보 우선, 끌기·놓기 안내를 확인. 테스트에서 패널을 화면에 띄우지 않았다.
- 제공된 v0.3.5 스크롤 기록의 재개 구간을 재생한다. 사용자 원본 좌표는 저장소에 넣지 않는다.

## 실제 사용 검증의 경계

자동 시험과 짧은 카메라 측정은 사용자의 손으로 목표 클릭·끌기·스크롤이 더 쉬워졌다는 검증을 대신하지 않는다. 카메라 촬영→입력 요청과 화면 표시까지의 체감 지연도 구분한다. 새 보정의 신체적 편안함, 손을 이용한 실제 앱 드래그/우클릭, 커서 옆 안내의 실사용 가독성은 사용자 동작으로 추가 확인해야 한다.

이번 도구의 AirTouch 실제 창 연결은 `Sky Computer Use native pipe closed before response`로 실패했다. 번들 ID나 권한을 변경해 우회하지 않았으며 자체 화면 렌더 결과와 실제 데스크톱 UI 검증을 구분한다.

## 실제 카메라 비교

모두 이 Mac의 내장 카메라와 Vision을 10초 실행했다. 테스트·컴파일을 동시에 실행하지 않았다. 측정에는 OS 이벤트를 전송하지 않는 가짜 출력 sink를 사용했다. 촬영 장면에서는 손이 검출되지 않았다. 720p → 480p → 720p 순서로 비교했으며 최종 세 실행 모두 끝까지 카메라 프레임이 도착하고 420v를 수신했다. 원본 이미지·손 좌표는 포함하지 않는다.

| 측정 | 실제 버퍼 | 촬영→입력 요청 중앙값 / p95 | Vision 중앙값 / p95 | 입력 요청 시간 표본 |
| --- | --- | --- | --- | --- |
| 형식 잠금 수정 전 v0.4.0 | 1920×1080 | 142.2 / 150.8ms | 16.5 / 26.9ms | 244 |
| 720p A | 1280×720 | 75.7 / 106.4ms | 9.8 / 25.2ms | 255 |
| 480p 비교 | 640×480 | 81.1 / 107.8ms | 21.4 / 30.0ms | 254 |
| 720p B | 1280×720 | 110.6 / 118.6ms | 9.3 / 24.3ms | 247 |

[수정 전 실제 1080p](v040-camera-format-reset-1080.json), [720p A](v040-camera-720-a.json), [480p](v040-camera-480.json), [720p B](v040-camera-720-b.json).

Vision 시간은 초기 60프레임을 제외한 표시 스냅샷에서 계산했고, 입력 요청 시간은 처리 큐의 전체 유효 표본(시작 구간 포함)이다. 따라서 열을 더하거나 빼서 단계별 차이를 계산하면 안 된다. 지연으로 제외된 프레임은 입력 요청 표본에 포함되지 않는다. 요청은 fake sink의 처리 완료 시각으로, CoreGraphics post·대상 앱 반응·물리 화면 표시 시간은 측정하지 않았다.

720p의 Vision 실행 시간은 두 번 모두 약 9~10ms였다. 그러나 카메라 전달 중앙값은 51.3ms에서 99.6ms로 변동했다. 전체 지연이 안정적으로 일정 비율 줄었다고 단정하지 않는다. 480p는 이 비교에서 추가 이점이 없어 기본값으로 선택하지 않았다. 더 낮은 해상도의 손가락 정확도도 확인하지 않았다. 기본은 실제 720p다.

[기존 v0.3.6 별도 측정](v040-camera-v036-baseline.json)은 촬영→UI 수신 중앙값 144.7ms / p95 171.4ms였지만 실제 해상도를 기록하지 않았고 단계·표본 조건도 다르다. 이를 최종 입력 요청 시간과 동일한 측정값으로 취급하지 않는다.

재현 실행 (기존 AirTouch를 완전히 종료한 뒤):

```bash
open -n ~/Applications/AirTouch.app --args --camera-benchmark --pipeline-benchmark --camera-benchmark-report /tmp/airtouch-camera-720.json
# 별도 실행에서만 --camera-480p 추가
```

일반 실행에서는 카메라나 실제 제어를 자동으로 시작하지 않는다.

## 설치본과 화면 확인

설치된 v0.4.0 build 10의 합성 손 시연은 660프레임, 클릭 1회, 드래그 완료 1회, 스크롤 353.6pt, 종료 시 버튼 해제였다. 드래그 잠금이 켜진 설정을 사용했다. `osInputEnabled=false`로 실제 OS 입력을 보내지 않았다. 카메라와 손쉬운 사용 권한은 해당 설치본 보고서에서 모두 승인 상태였다. [설치본 시연](v040-demo.json).

엄격한 코드 서명 검증, 이전 v0.3.6과 동일한 designated requirement, 빌드 실행 파일과 설치본의 39개 Mach-O 섹션 내용 일치를 확인했다. 임시 서명과 개발 서명에 따른 파일 메타데이터 차이가 있으므로 실행 파일 전체 SHA-256 일치로 표현하지 않는다. 설치본 해시는 기록했다. 최종 실행·등록 경로는 `~/Applications/AirTouch.app` 하나이며 임시 패키지와 설치 중 백업이 없다. 휴지통의 옛 앱이 실행 목록에 다시 등록되어 있어 해당 등록만 해제했다. [최종 설치 상태](v040-install-state.json).

자체 뷰의 오프스크린 렌더: [보정 시작](v040-calibration-intro.png), [진행](v040-calibration-progress.png), [완료](v040-calibration-completed.png). 실시간 카메라나 데스크톱 조작 성공의 증거로 사용하지 않는다.
