# v0.3.3 조작 개선 검증

사용자가 커서 이동부터 클릭·스크롤까지 전체적으로 어렵다고 보고했다. 현재 제공된 사용자 JSON은 v0.3.0 연습 기록이며 마지막 600프레임이 손 미검출 구간이다. 이번 개선은 최신 사용자 동작을 재생한 결과가 아니라, 명시한 조작 시나리오를 순수 입력 엔진에 넣어 검증한 결과다.

## 수정 전후 비교

실행 명령: `DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer swift test --filter ComfortableControlTests`

| 합성 입력 조건 | v0.3.2 | v0.3.3 편안하게 |
| --- | --- | --- |
| 손 중심 고정, 검지 끝만 9프레임에 걸쳐 구부리기 | 커서 약 51.7pt 이동 | 커서 위치 유지 |
| 손을 같은 거리만큼 느리게 / 빠르게 이동 | 약 345 / 345pt | 약 146 / 583pt |
| 클릭 중 손을 영상 너비의 0.4%만큼 이동 | 드래그 발생 | 한 번의 클릭, 위치 유지 |
| 스크롤 자세에서 ±0.15%의 미세 떨림 | 입력 절댓값 합계 약 35.8pt | 스크롤 입력 없음 |

화면 크기 1800×1125pt, 감도 1.6, 30fps로 검증했다. 속도 비교는 영상 너비의 12%를 각각 3초와 0.4초에 이동한 뒤 필터 잔여분을 관찰한 결과다. 수치는 손 움직임과 커서의 변환 특성을 설명하며 카메라 지연이나 체감 편의성 측정은 아니다.

[수정 전 실패 로그](v033-usability-red.log), [전체 54개 테스트](v033-tests.log).

## 구현

- 기본 조작은 검지 끝 대신 손목·검지 밑관절·중지 밑관절로 구한 손 중심을 사용한다. 기존 검지 자세, 펼친 손으로 쉬기, 손 상실 시 해제 조건은 유지한다.
- 이동 속도에 따라 연속적으로 감도를 조절한다. 카메라 시간 간격을 사용하며 15·30·60fps에서 이동량 차이가 10% 이내임을 검증했다.
- 드래그 시작 허용폭은 화면 크기 대신 손 크기를 기준으로 잡는다. 의도적 드래그와 버튼 해제, 해제 후 커서 재개도 검증했다.
- 스크롤 기준점 주위의 작은 움직임을 허용한다. 느린 의도적 스크롤, 반대 방향 전환, 포인터 복귀는 각각 검증했다.
- 기존 손끝 추적과 일정한 감도는 ‘손끝으로 직접’으로 보존했다. 기존 테스트 중 해당 방식에 의존하는 사례는 이를 명시하고, 손 중심 방식의 시나리오는 별도 검증했다. 관절 추출부터 시스템 출력 게이트까지의 통합 입력은 손 전체가 움직이는 좌표를 사용한다.
- Mac 제어 화면과 설정에서 방식을 선택하고 저장한다. 보고서에 `controlStyle`을 기록한다. 기존 감도와 스크롤 방향 설정은 보존한다.

## 설치본 검증

Release 빌드 및 서명 검증을 통과했다. 같은 앱 ID와 개발 서명 요구사항을 유지하고, 설치 앱 한 개와 임시 패키지 제거를 확인했다. [설치 로그](v033-install.log), [설치 상태](v033-install-state.json).

처음 설치본에서 `--demo` 완료 보고서가 생성되지 않았다. 실행 옵션 처리가 `ContentView.onAppear`에 묶여 있었으므로, 창 복원과 무관하게 데모 옵션을 처리하도록 수정했다. 중복 실행 방지 상태는 유지한다.

수정 후 설치본 데모 660프레임에서 클릭 1회, 드롭 1회, 스크롤 약 349.5pt, 마지막 버튼 해제를 확인했다. 기본 `comfortable`와 카메라·손쉬운 사용 허용도 앱 보고서에서 확인했다. 이 데모는 OS 입력을 전송하지 않았다. [설치본 합성 데모 보고서](v033-demo.json).

자동 UI 도구는 앱 ID로 연결하면 `Invalid app: dev.airtouch.mac`, 현재 설치 경로로 연결하면 이전 ID인 `dev.airtouch.practice`를 찾는 오류를 반환했다. 도구 세션 초기화 후에도 같았다. 따라서 새 설정 화면의 시각적 배치와 실제 손으로 하는 macOS 제어 편의성은 미검증이다. 실제 OS 제어의 성공을 합성 테스트로 대신 주장하지 않는다.
