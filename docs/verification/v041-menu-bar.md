# v0.4.1 메뉴 막대 상주 검증

검증일: 2026-09-17 · 버전: 0.4.1 · 빌드: 11

## 변경

기존에는 첫 SwiftUI `Window`가 제어 창을 만들고, 창의 `onAppear`에서 앱을 `.regular`로 바꾸고 활성화했다. 메뉴 막대 아이콘이 있어도 Dock과 큰 창이 함께 남는 원인이었다.

- `LSUIElement=true`와 `.accessory` 실행 정책을 사용한다. 메뉴 막대의 시작·중지·화면 열기·설정·종료가 기본 진입점이다.
- 제어 창은 요청할 때 한 개만 만들고 재사용한다. 창의 자동 복원을 끄고, 마지막 창을 닫아도 앱을 종료하지 않는다.
- 앱 시작 처리를 창에서 application delegate로 옮겼다. 첫 사용 준비 또는 권한 부족 때만 안내 창을 자동으로 연다. 진단 실행도 창 생성과 분리했다.
- 전체 제어를 시작하면 열려 있던 제어 창을 숨긴다. 이후 사용자가 요청하면 다시 열 수 있다. 기존 전체 제어의 창 닫기·초점 상실 정책은 유지한다.
- 설정은 SwiftUI Settings를 유지하고, 설정에서 손 보정·권한 안내로 돌아오는 경로를 새 창 관리에 연결했다. 제어 창의 기존 키 조합과 ⌘W·⌘,도 처리한다.

macOS 14를 계속 지원한다. 15 이상에서만 쓸 수 있는 `defaultLaunchBehavior(.suppressed)`에 의존하지 않고 AppKit으로 창의 생성 시점을 제어한다. [MenuBarExtra](https://developer.apple.com/documentation/swiftui/menubarextra), [LSUIElement](https://developer.apple.com/documentation/bundleresources/information-property-list/lsuielement)

## 설치 결과와 남은 확인

설치 위치는 `~/Applications/AirTouch.app`이다. 임시 `.app` 패키지와 설치 백업은 제거됐고, 휴지통에 있던 이전 앱의 실행 등록을 해제해 현재 설치 경로만 등록된 것을 확인했다. 휴지통 파일을 영구 삭제하지는 않았다. 진단 실행 후 일반 인수로 다시 실행해 둔 상태다.

화면 조작 도구가 `native pipe closed` 및 재시도 `timeout -10005`로 실패했다. 따라서 메뉴 항목의 실제 클릭, 설정 창의 실제 전면 표시, 최초 권한 안내, 제어 시작 때 창 숨김, 실제 손 제어를 계속하면서 창을 닫는 과정은 이 릴리스에서 직접 화면 조작으로 확인하지 못했다. 해당 동작의 소스·빌드 확인과 숨긴 창의 컴포넌트 테스트를 실제 사용 검증과 구분한다.

창을 다시 열려면 메뉴 막대의 손 아이콘에서 **제어 화면 열기…**, 앱을 종료하려면 **AirTouch 종료**를 사용한다.
