# v0.3.5 시작 중지와 추종 지연

## 사용자 기록

사용자는 이전보다 훨씬 부드러워졌지만 느리게 따라오고, 시작하면 앱 창은 남은 채 카메라·제어가 중지된다고 보고했다. 새 v0.3.4 기록은 권한 허용·실제 Mac 제어 상태이며 991프레임, 유효 손 508프레임, 지연 제외 47프레임, 입력 요청 315개였다.

동작 기록에서 촬영→캡처 콜백 중앙값 약 125ms, Vision 계산 약 16ms, 메인 큐 전달 약 17ms였다. 전체 세션의 촬영→Vision 완료 P95는 약 165ms였다. 원본 손 좌표는 Git에 포함하지 않는다. 이 기록에는 종료 안내 문구가 없어서 사용자가 겪은 종료 원인 전체를 단정할 수는 없다.

## 재현한 출력 시작·중지 문제

기존 출력 게이트는 `begin(now:)`의 시각을 마지막 촬영 시각으로 초기화했다. 이후 바로 전달하는 첫 영상은 이미 160ms 전에 촬영됐으므로 ‘이전 촬영’으로 거부됐다. 새 세션 ID 확인과 영상 나이 확인은 유지하고, 촬영 순서의 초기값을 분리했다.

다른 재현에서는 촬영 후 180ms에 도착한 영상을 처리하고 90ms 뒤 감시기를 실행했다. 영상은 90ms 동안만 오지 않았지만 촬영부터는 270ms가 지나 전체 출력이 종료됐다. 영상 수신 시각으로 연속성을 판단하도록 수정했다. 실제 250ms 수신 중단, 권한 철회, 누른 버튼의 오래된 손 정보에 대한 해제 기준은 유지한다. 같은 촬영 시각을 반복해도 수신 유효기간을 연장할 수 없다.

`swift test --filter 'SystemOutputGateTests.testFirstFresh|SystemOutputGateTests.testContinuousDelivery|ResponsivenessTests.testFilterResponds'`로 수정 전 실패를 확인했다. [수정 전 로그](v035-red.log).

## 필터

동작 속도에 따른 cutoff 계수 beta를 12 → 24로 변경했다. 정지 시 minimum cutoff 1.5는 그대로다. 영상 정규화 좌표를 초당 0.25만큼 30fps로 이동한 테스트에서 평균 필터 지연은 약 35.4 → 21.2ms였다. 정지 잡음, 오버슈트 없음, 정밀/큰 이동, 클릭·스크롤 회귀도 통과했다. 이 값은 촬영과 OS 표시를 포함한 전체 지연이 아니다.

## 실제 카메라 형식 비교

이 Mac의 FaceTime HD 카메라는 확인한 모든 형식에서 최대 30fps였고 기본 픽셀 형식은 420v였다. 720p/30fps와 Vision을 유지하고 출력 버퍼만 BGRA 또는 420v로 바꿨다. Apple은 기본 캡처 형식이 아닌 BGRA에 불필요한 변환과 메모리 비용이 발생할 수 있음을 설명한다. [Apple TN3121](https://developer.apple.com/documentation/technotes/tn3121-selecting-a-pixel-format-for-an-avcapturevideodataoutput).

측정은 설치된 동일 앱에서 각 10초, 초기 60프레임을 제외했다. 실제 카메라+Vision 경로이며 OS 입력을 전송하지 않는다. 영상과 손 좌표는 저장하지 않고 아래 시간 통계만 저장한다. 측정 시 손이 없는 장면이었으므로 손 인식 정확도나 실제 조작 성공의 증거가 아니다.

| 측정 | 영상 전달 중앙값 | Vision 중앙값 | 메인 큐 중앙값 | 촬영→수신 중앙값 / P95 |
| --- | ---: | ---: | ---: | ---: |
| BGRA 첫 실행 | 80.1ms | 11.2ms | 13.8ms | 104.0 / 147.1ms |
| 기본 420v | 101.0ms | 13.2ms | 0.05ms | 113.9 / 125.2ms |
| BGRA 재측정 | 93.4ms | 16.4ms | 12.3ms | 119.9 / 145.4ms |

첫 BGRA 측정에는 초반 테스트 빌드 작업이 겹쳐, 빌드 없이 BGRA를 다시 측정했다. 짧은 비교에서 420v의 메인 큐 대기와 전체 수신 P95가 낮았지만, 전체 중앙값은 실행마다 달랐다. 형식 변경으로 지연 전체가 일정 비율 줄었다고 일반화하지 않는다. 영상 내용·부하에 따른 실사용 검증은 남아 있다.

[BGRA 첫 실행](v035-camera-bgra.json), [420v](v035-camera-native.json), [BGRA 재측정](v035-camera-bgra-repeat.json).

개발 측정 실행: 앱을 종료한 뒤 `open -n ~/Applications/AirTouch.app --args --camera-benchmark --camera-benchmark-report /tmp/camera-timings.json`. BGRA 비교는 `--camera-bgra`를 추가한다. 측정은 10초 뒤 카메라를 중지한다. 이 옵션은 사용자 화면에 추가하지 않는다.

## 검증 범위

자동 테스트 65개 통과. v0.3.3 원본 파일이 필요한 선택적 로컬 재생 1개는 건너뛰었다. 현재 사용자가 제공한 파일은 v0.3.4이므로 서로 다른 기록을 같은 재현 사례인 것처럼 사용하지 않았다. [전체 테스트](v035-tests.log).

진단 보고서에는 `isRunning`, `status`, `engineReason`을 추가해, 앞으로 실제 종료 문구와 엔진 대기 이유를 구분할 수 있게 했다. 새 버전의 실사용 추종 감각과 사용자 환경에서 시작 중지가 완전히 사라졌는지는 추가 확인이 필요하다.

최종 설치본 v0.3.5는 동일한 서명 요구사항과 설치 앱 1개를 유지했다. 데모 660프레임이 클릭 1회·드롭 1회·스크롤·최종 버튼 해제로 완료됐고 카메라·손쉬운 사용 허용을 확인했다. [설치 로그](v035-install.log), [설치 상태](v035-install-state.json), [설치본 합성 데모](v035-demo.json).
