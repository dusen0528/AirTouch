# v0.4.6 전체 제어 중 일시적인 영상 지연 복구

## 사용자 증상과 확인 범위

사용 중 전체 제어가 꺼져 직접 다시 시작해야 한다는 보고를 받았다. 이번 세션에서 최신 `airtouch-session.json`은 아직 확보하지 못했으므로, 해당 실제 중단의 단일 원인을 확정한 기록은 아니다.

실제 출력 디스패처를 가짜 시계·권한 검사·출력 수신기로 실행해 동일한 종류의 종료 요청을 재현했다. 테스트는 카메라 영상이나 사용자 손 좌표를 사용하지 않으며 CGEvent를 생성·전송하지 않는다.

## 수정 전 재현

```sh
DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer swift test --filter SystemInputDispatcherTests
```

[수정 전 로그](v046-output-red.log): 2개 테스트, 2개 실패.

1. 새 입력 전달이 250ms 이상 끊기면 최종 입력 게이트가 닫혔고, 디스패처가 이를 권한 철회와 동일한 `onFault`로 통보했다. AppModel은 이 콜백에서 전체 제어와 카메라를 종료했다. 일시 지연에서 전체 종료 요청이 없어야 한다는 검사가 실패했다.
2. 권한 철회가 프레임 처리 중 발견되면 게이트는 닫히지만 콜백을 보내지 않았다. 이후 타이머는 이미 닫힌 게이트를 건너뛰어 전체 종료 통보가 누락됐다.

카메라 자체의 세션 오류·중단, 실제 화면 구성 변경, 잠금·잠자기, 권한 철회는 별도 종료 경로다. 이번 수정은 일시적인 출력 지연을 전체 종료로 확대하던 경로를 다룬다.

## 변경

- 시간 초과와 권한 철회를 서로 다른 출력 중단 원인으로 전달한다.
- 기존 안전 제한은 유지한다. 새 프레임 전달이 250ms 이상 끊기거나, 눌린 상태에서 유효 손의 촬영 시각이 200ms 이상 오래되면 입력을 차단하고 눌린 버튼을 즉시 해제한다.
- 시간 초과는 카메라와 인식 세션을 유지하면서 제스처 엔진을 준비 상태로 되돌린다. 현재 커서 위치에서 새 영상과 정상 준비 자세를 확인한 뒤 재개한다. 중단된 집기·드래그를 자동으로 이어 누르지 않는다.
- 복구 전에 촬영된 영상과 이전 출력 세션의 늦은 통보는 무시한다. 명시적 중지 뒤에는 대기 중인 콜백으로 다시 켜지지 않는다.
- 권한 철회는 전체 중지를 유지한다. 권한이 다시 허용돼도 사용자가 직접 시작하기 전에는 제어하지 않는다.
- 타이머뿐 아니라 프레임·해제 처리에서도 게이트가 닫힐 때 중단 이유를 한 번 전달한다.
- 복구 대기 횟수는 기존 진단의 `interruptionReasons`에 집계한다.

## 검증 경계

출력 디스패처·컨트롤러·최종 게이트의 실제 구현을 합성 입력으로 연결한 회귀 검증이다. AppModel의 카메라 유지 분기는 코드 검토 대상이며 실제 손을 사용한 긴 세션이나 대상 앱의 입력 성공을 이 테스트로 주장하지 않는다. 긴급 중지, 권한 철회, 잠금 및 실제 카메라 세션 중단은 사용자가 직접 다시 시작하는 기존 방식을 유지한다.

## 자동 테스트 결과

```sh
DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer swift test --filter 'SystemInputDispatcherTests|SystemTrackingRecoveryTests'
./scripts/test.sh
```

- 출력 디스패처 14개 + 실제 컨트롤러 연계 6개, 총 20개 통과. [회귀 로그](v046-output-green.log).
- 전체 163개 실행, 161개 통과·사용자 원본이 필요한 2개 건너뜀·실패 0. [전체 로그](v046-tests.log).
- 같은 세션에서 5회 연속 지연 후 복구, 눌림 해제 1회, 집은 상태로 복귀해도 새 클릭 없음, 새 자세 유지 후 이동 재개를 확인했다.
- 권한 복구만으로 자동 재시작되지 않음, 기존 출력 세션의 늦은 통보 무시, 복구 전에 촬영된 프레임 거부를 확인했다.
- 앱의 실제 카메라와 대상 앱에 대한 OS 입력은 이 테스트에서 실행하지 않았다.
