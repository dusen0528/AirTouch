# v0.3.4 이동 끊김 검증

## 사용자가 제공한 근거

v0.3.3 ‘편안하게’, 카메라와 손쉬운 사용 허용, `osInputEnabled=true`인 실제 Mac 제어 세션이다. 1,415프레임 중 유효 손 983프레임, 지연 제외 27프레임, 입력 요청 99개, 물리 마우스 양보 2회가 기록됐다. 입력 요청 수는 다른 앱의 처리 성공 횟수가 아니다.

마지막 동작 기록 1,123프레임에서 확인한 사실:

- 일반 이동 중 엄지와 접힌 중지의 거리가 가까워져 우클릭 후보로 넘어가고, 이동 때문에 취소되어 대기로 떨어졌다. 예: sequence 442 → 445 → 446.
- sequence 1107은 손이 유효하고 검지 이동 자세였으며, 현재 영상 나이는 약 176ms였다. 직전 수신으로부터 약 79ms가 지났지만 이전 영상의 촬영 시점으로는 약 209ms가 지나 watchdog이 ‘영상이 멈춤’으로 판정했다.
- `isOpenPalm=true`가 253프레임 있었고 사용자는 검지만 펴고 이동했다고 확인했다. 이전 기록은 관절 좌표를 포함하지 않아 이 구간의 관절 판정을 원본 그대로 재생할 수 없다.
- 촬영부터 Vision 완료까지 P95 약 146ms. 동작 기록 내 Vision 자체는 중앙값 약 17ms, UI 전달은 중앙값 약 16ms였다. 이번 변경으로 카메라 지연 자체가 줄었다고 주장하지 않는다.

사용자 원본 JSON과 손 좌표는 Git에 넣지 않았다.

## 재현과 수정

실제 기록 재생 명령:

```bash
AIRTOUCH_REPLAY_PATH=/path/to/exported-session.json ./scripts/test.sh
```

로컬 기록 테스트는 이번 v0.3.3 세션의 sequence 1088–1114를 선택한다. 활성화 시간을 제외하고 확인하는 13프레임에서 v0.3.3은 10프레임이 대기 상태였고 수정 후에는 0프레임이다. 파일을 지정하지 않은 일반 테스트에서는 이 한 사례만 건너뛴다. 원본 좌표는 실행 시 읽고 출력하지 않는다.

원본 타이밍을 단순화한 합성 테스트도 추가했다. 정상적으로 전달되는 이동 영상의 나이가 130/176/143ms로 변할 때 재활성화 대기가 생기는 문제를 재현했고, 수신 시각 기준으로 연속성을 확인하도록 수정했다. 200ms 이상 오래된 새 영상은 여전히 거부하며, 버튼을 누른 동안의 촬영 시각 기반 해제는 유지한다. 프레임이 실제로 오지 않으면 손 상실 기준으로 포인터가 중단되는 것도 검증했다.

‘편안하게’에서는 우클릭 전에 검지·중지를 펼친 자세를 100ms 이상 확인한다. 준비 상태는 700ms 후 만료되며 한 번 사용하면 소비한다. 스크롤 진입 전과 후 모두 준비한 우클릭이 한 번 발생하고 주 클릭을 만들지 않는지 검증했다. 기존 ‘손끝으로 직접’의 동작은 유지한다.

유효 손의 손가락 자세만 일시적으로 불확실하면 120ms 이내에는 손 중심 이동을 이어간다. 이 유예로 클릭을 만들지는 않는다. 긴 불확실성, 명확한 펼친 손, 실제 영상·손 상실은 중지한다.

접힌 손가락이 카메라 평면에서 곧은 선으로 보이되 손끝은 손목 쪽을 향하는 합성 관절 사례를 추가했다. 이전 판정은 이를 펼친 손으로 읽었다. 손끝과 손목·밑관절 사이 거리도 확인하도록 보완했다. 실제 사용자의 해당 관절은 기록에 없으므로 이 수정의 실제 인식 개선 여부는 새 카메라 기록이 필요하다.

## 검증 결과

- 테스트 62개 통과: 일반 테스트 61개와 로컬 사용자 기록 재생 1개.
- 기존 클릭·드래그·스크롤·우클릭·권한 철회·오래된 입력 차단·출력 해제 회귀 통과.
- 앱의 지연 표시도 수신 시각을 기준으로 변경했다. 수동 저장하는 진단 기록에는 관절 위치·신뢰도와 중지 원인 횟수를 추가했다. 영상은 저장하지 않는다.

[이동 수정 전](v034-continuity-red.log), [손 모양 수정 전](v034-pose-red.log), [전체 테스트](v034-tests.log), [설치 로그](v034-install.log).

이 기록 재생은 실제로 내보낸 손 좌표와 타이밍을 엔진에 다시 넣는 검증이다. 새로운 카메라 세션의 체감, 실제 OS 화면의 커서 움직임, 모든 끊김의 해소를 의미하지 않는다.

최종 설치본 v0.3.4의 데모 660프레임도 클릭 1회·드롭 1회·스크롤·버튼 해제로 끝났으며 카메라와 손쉬운 사용 허용을 확인했다. 같은 개발 서명 요구사항과 설치 앱 1개를 유지했다. [설치 상태](v034-install-state.json), [합성 데모](v034-demo.json).

확정한 재현 테스트를 v0.3.3 소스만 추출한 별도 임시 패키지에서도 실행했다. 타이밍 합성 사례와 사용자 기록 재생이 모두 실패하는 것을 재확인했다. [정확한 이전 버전 비교](v034-precise-baseline.log).
