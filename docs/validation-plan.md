# AirTouch 검증 계획

현재 측정 결과 없음. 아래 수치는 초기 목표이며 실기기 결과를 기입하기 전까지 성능 주장에 사용하지 않는다.

## 1. 이벤트 계약 검증

카메라를 연결하지 않고 타임스탬프가 포함된 랜드마크와 장애 이벤트를 순서대로 재생한다. 테스트에서는 가짜 시계를 사용해 프레임 속도와 관계없이 전이를 재현한다.

| 입력 시나리오 | 기대 결과 |
| --- | --- |
| 활성화 전에 핀치 | OS 입력 0회 |
| 확정 시간보다 짧은 핀치 | down/up 0회 |
| 확정된 핀치 1회 후 해제 | down 1회, up 1회 |
| 핀치를 3초 유지 | down은 총 1회, 해제 전 up 0회 |
| 핀치 유지 후 손 이동·해제 | down → dragged들 → up. 별도 클릭 쌍 없음 |
| 임계값 사이에서 거리 진동 | 이전 핀치 상태 유지, 반복 down/up 없음 |
| 핀치 상태에서 두 손가락 자세처럼 오인식 | 스크롤 이벤트 0회 |
| 스크롤 자세로 진입하기 전 손 이동 | 진입 시 과거 이동량 출력 없음 |
| 스크롤 자세 해제 | 스크롤 즉시 중지, 잔여 이동량 폐기 |
| 누름 중 유효 손 상실 120ms | up 1회 시도 후 일시정지 |
| 영상 전달 중단 200ms | 프레임 콜백 없이 watchdog으로 입력 정리 |
| 중지·손 상실·종료 이벤트 연속 도착 | 눌렀던 버튼당 해제 최대 1회 |
| 중지 이후 이전 세션의 추론 결과 도착 | 모든 입력 폐기 |
| 휴식 후 다른 위치에서 손 재등장 | 커서 유지, 재활성화 전 입력 없음 |
| 두 손이 교차해 동일 손 판정 불확실 | 임의의 손으로 제어 이전 없이 정지 |
| 15/30/60fps 및 불규칙 간격 | 유지 시간 기반으로 같은 의미의 상태 전이 |

## 2. 좌표와 움직임 검증

알려진 좌표를 입력해 상하좌우 방향, 거울 반전, 화면 경계, 음수 디스플레이 원점, 스케일 변경을 확인한다. 미세한 일방향 이동이 dead zone에서 영원히 소실되지 않아야 한다. 화면 경계에서 오래 움직였다가 반대 방향으로 돌렸을 때 즉시 반응해야 한다.

좌표 필터는 정지, 일정 속도, 빠른 이동, 갑작스러운 이상점, 긴 프레임 공백으로 평가한다. 상대 이동·절대 이동을 같은 과제로 비교하되, 절대 이동 모드도 재활성화 점프를 따로 기록한다.

## 3. 실기기 과제와 초기 목표

화면 좌표 단위는 입력 시스템과 일치시킨다. 앱 안의 목표 크기를 보고용으로 pt라고 표기할 때에는 CoreGraphics 이벤트 좌표로의 변환을 확인한다.

| 지표 | 측정 방법 | 초기 목표 |
| --- | --- | --- |
| 처리 지연 | 캡처 타임스탬프부터 이벤트 전송 직전까지 동일 시계로 계측 | p95 ≤ 80ms, 의도적인 제스처 유지 시간 제외 |
| 시각 반응 지연 | 필요 시 외부 고속 촬영으로 실제 손 움직임과 화면 반응 비교 | 기준선 확보 후 목표 설정 |
| 정지 떨림 | 같은 자세로 10초씩 5회, 출력 좌표의 중앙값 대비 반경 p95 | ≤ 6 좌표 단위 |
| 클릭 성공 | 32·44·64pt 목표를 무작위 위치로 각각 20회 제시, 의도한 한 번만 누른 비율 | 44·64pt에서 ≥ 95%, 32pt는 한계 기록 |
| 드래그 성공 | 연습 상자 20회, 실제 창 20회 이동 후 의도한 위치에 놓기 | 각각 ≥ 90% |
| 스크롤 혼동 | 이동↔스크롤 전환 30회, 불필요 클릭·커서 이동 기록 | 혼동 0회 |
| 비의도 입력 | 대기·휴식·활성 상태를 나눠 대화, 얼굴 만지기, 손 내리기 관찰 | 각 10분 세션에서 오클릭 0회 |
| 재개 점프 | 손을 내렸다 다른 위치에서 올리기 30회 | 재활성화 시 커서 점프 0회 |
| 장애 복구 | 가림·영상 정지·권한 변경 등 각 10회 | 정상 실행 중 눌림 잔류 0회 |
| 지속 사용 | 문서 읽기·링크 클릭·창 이동으로 10분 과제 | 완료율과 팔 피로 1~5점 기록, 중앙값 ≤ 2 목표 |

핀치 확정 대기 80ms는 처리 지연과 별도로 보고한다. “80ms 앱”처럼 전체 체감 지연과 혼동될 표현을 쓰지 않는다. 낮은 표본의 0회 실패는 실패 확률이 0이라는 증거가 아니다.

첫 사용성 비교는 가능하면 손 크기와 사용 손이 다른 5명으로 진행한다. 한 사람만 평가했다면 개인 실험으로 표시한다. 트랙패드 기준선과 비교하고, 조건 순서를 번갈아 배치해 연습 효과를 줄인다. 좁은 Active Zone이 실제로 팔 피로를 낮추는지는 직접 측정한다.

## 4. 환경 매트릭스

- 보통 조명, 어두운 조명, 역광에서 성공률과 추적 중단률 분리 기록.
- 가까운 거리, 기본 거리, 먼 거리와 손 회전·화면 가장자리·부분 가림.
- 왼손·오른손, 두 손 동시 등장, 다른 사람이 배경에 들어오는 경우.
- 실제 내장 카메라 기종과 macOS 버전. 테스트하지 않은 MacBook까지 일반화하지 않음.
- 기본 화면, 외부 화면 선택, 음수 원점 배치, 해상도·배율 변경, 연결 해제.
- Safari·Chrome·Finder·문서 앱에서 클릭·드래그·스크롤 반응 차이.
- 카메라 사용 중 다른 앱 시작, 잠자기·복귀, 화면 잠금, 카메라 중단.
- 카메라 및 손쉬운 사용 권한 거부·철회·재허용, 서명 앱 재실행.
- 물리 마우스·트랙패드 사용, 전역 중지 단축키, 합성 이벤트 재감지 여부.
- 정상 종료와 강제 종료를 구분해 입력 상태 확인. 강제 종료 복구를 보장했다고 표현하지 않음.

CPU, 메모리, 전력 영향, 온도 상태, 실제 추론 FPS를 10분 이상 기록한다. 프리뷰 열림·닫힘과 쉬기·활성 상태를 구분한다. 기종별 기준선이 나오기 전까지 고정 배터리 소모량을 약속하지 않는다.

## 5. 결과 기록 형식

각 실행에 앱 버전, 기기, OS, 카메라 포맷, 조명, 거리, 손 설정, 파라미터, 과제 수, 성공 수, 실패 이유, 처리 지연 p50/p95, 중단 횟수, 자원 사용, 피로 점수를 남긴다.

실패 이유는 추적 실패, 잘못된 제스처 전환, 커서 불안정, 입력 전송 문제, 대상 앱 동작 차이로 분리한다. 원인 미확인은 그대로 미확인으로 남긴다. 영상 재생 테스트 통과와 실제 OS 조작 성공을 별도 결과로 기록한다.

## 6. 다음 개발로 넘어가는 기준

단위·재생 테스트 통과만으로 제품 검증을 끝내지 않는다. 실제 기기에서 활성화 → 이동 → 클릭 → 드래그 → 스크롤 → 휴식 → 재개 흐름을 통과해야 한다.

오클릭, 버튼 눌림 잔류, 재개 점프가 남아 있으면 새 제스처 추가를 보류한다. 피로가 높으면 손의 작업 위치·감도·상대 이동 방식을 먼저 바꾼다. Vision의 관절 검출이 병목으로 확인되면 동일한 입력 자료와 같은 평가 조건으로 대체 엔진을 비교한다.
