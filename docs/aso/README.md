# AirTouch 검색 유입과 전환 준비

2026-09-17 · v0.4.0 기능 기준 · 스토어에 게시하지 않은 로컬 준비물.

## 현재 판단

검색량보다 **검색 의도에 맞는 기능 → 처음 써서 동작하는 경험 → 전환 확인 → 검색어 확장** 순서로 진행한다. 현재의 Mac 전체 제어는 Mac App Store Sandbox 요구와 충돌하므로 배포 경로부터 확정해야 한다. [현재 구현과 공식 배포 규칙](distribution.md).

기능을 유지한 외부 배포를 선택한다면 같은 메시지와 검색 의도를 소개 페이지에 활용할 수 있다. 이때 웹 검색 유입·다운로드 클릭·첫 실행 성공은 App Store 순위·설치 전환과 다른 지표다. 아직 외부 사이트를 만들거나 게시하지 않았고, 사용자가 배포 경로를 선택한 것으로 간주하지 않는다.

## 적용한 문구와 검색어

- 이름: **AirTouch · 손동작 마우스**
- 부제: **MacBook 카메라로 커서·클릭·스크롤**
- 키워드 필드: `핸즈프리,제스처,포인터,드래그,터치리스,비접촉`
- 우선 조사할 의도: `손동작 마우스`, `카메라 마우스`, `제스처 마우스`

우선순위는 제품과의 관련성 판단이다. 검색량·난이도·현재 순위·상위 10위 진입 가능성을 측정한 결과가 아니다. 이름·부제에 있는 표현을 키워드 필드에 반복하지 않고 서로 보완한다. 첫 대상은 한국·한국어로 좁혔다. 영어 UI 현지화나 해외 사용 경험은 별도 확인 대상이다.

[등록용 소개문 전체](listing-preview.md) · [편집할 원본 JSON](../../store/metadata/ko-KR.json) · [검색어와 확장 기준](../../store/aso-plan.json)

사용 경험을 보여줄 첫 화면 세 장의 기획:

| 순서 | 전할 내용 | 확보할 실제 장면 |
| --- | --- | --- |
| 1 | 내장 카메라로 손동작을 마우스로 | 커서 이동·클릭·세로 스크롤을 수행하는 실제 앱 화면 |
| 2 | 편한 손 움직임에 맞추기 | 개인 보정 시작과 적용 결과 |
| 3 | 계속 집고 있지 않아도 되는 끌기 | 끌기 잠금 안내와 실제 놓기 완료 |

v0.4.0의 합성 데모·오프스크린 렌더를 실제 손 성공 장면으로 표시하지 않는다. ‘지연 없음’, ‘트랙패드 완전 대체’, 의료 효과, 미지원 눈·음성 추적은 문구에서 제외했다. 현재 스크린샷은 기획 단계다.

## 데이터가 연결되면 실행할 순서

1. **배포 확인:** 공개 상품 페이지·앱 ID, 지원/개인정보 URL, 실제 제공 기능을 확인한다. 현재 미확인 칸은 `null`로 유지한다.
2. **후보 조사:** 같은 한국 Mac App Store 결과로 첫 세 검색어를 관측한다. 순위·조회 깊이·관측 일시·출처를 [관측표](../../store/keyword-observations.template.csv)에 남긴다. 조회 범위 밖은 ‘미관측’, 오류는 ‘조회 실패’로 구분한다. 메타데이터에 넣었다고 색인 완료로 표시하지 않는다.
3. **기준값 확보:** 같은 플랫폼·국가·기간의 App Store search 집계를 확보한다. 첫 다운로드와 재다운로드가 포함된 총 다운로드, 고유 노출과 사전 주문을 구분한다. **검색어별 실제 설치 전환은 제공이 확인되지 않았으므로 계산하지 않는다.**
4. **한 묶음 변경:** 기존 문구·적용 시각·가설을 기록한 후 하나의 검색 의도 묶음만 바꾼다. 가격·광고·기능 변경도 같이 기록해 원인을 혼동하지 않는다. App Store 실제 저장·반영은 로컬 파일 수정과 별도로 확인한다.
5. **주간 검토:** 같은 기간 길이와 정의로 순위·집계 전환·첫 사용 성공을 비교한다. 자료가 부족하면 문구를 억지로 바꾸지 않는다. 여러 관측에서 의도가 맞고 첫 사용에 문제가 없을 때 다음 후보를 검토한다. 전후 비교는 무작위 A/B 검증이 아니다.

개인 보정과 첫 클릭·끌기·스크롤이 어렵다는 피드백이 있으면 소개를 과장해 설치를 늘리기보다 그 실패부터 고친다. 첫 사용 평가는 로컬 수동 기록으로 시작하며, 마케팅 작업을 이유로 카메라·손 좌표 원격 수집을 추가하지 않는다.

## 로컬 검증과 집계

```bash
python3 scripts/aso.py check
python3 scripts/aso.py preview
# 미완료 제출 항목이 남아 있어 현재는 실패하는 것이 정상이다.
python3 scripts/aso.py check --ready

# 템플릿을 복사하고 ASC에서 확인한 동일 기간의 집계값을 입력한다.
mkdir -p store/local
cp store/search-metrics.template.csv store/local/search-metrics.csv
python3 scripts/aso.py metrics --input store/local/search-metrics.csv
```

CSV는 ASC 원본을 자동 해석하는 형식이 아니라 [템플릿](../../store/search-metrics.template.csv)에 맞춰 정리한 집계 입력이다. `period_start/end`는 ISO 날짜, `platform`은 `MAC_OS`, `territory`는 `KR`, `source_type`은 `App Store search`로 입력한다. `source_reference`에 원본 파일명이나 출처를 남긴다. 고유 노출·총 다운로드·사전 주문은 같은 기간과 필터의 값이어야 한다. 미제공 칸은 비워두고 실제 0만 `0`으로 쓴다. 사전 주문이 없다는 사실도 확인한 뒤 0으로 입력한다.

계산식은 `(총 다운로드 + 사전 주문) / 고유 기기 노출 × 100`이다. 공식 제공값과 입력 범위를 대조해야 하며 사전 주문의 후속 다운로드 중복을 직접 더하지 않는다. 검색 광고가 포함될 수 있어 ‘순수 자연 유입’으로 부르지 않는다. 분모 0·누락값은 전환율 미확인으로 반환하며, 기간별 고유 노출을 합산하지 않는다. `store/local/`은 Git에서 제외했다. [공식 지표와 지원 범위](research.md).

## Applyra 연결 상태

공식 MCP는 있지만 이번 세션에 연결되지 않았다. 플러그인 디렉터리에서도 Applyra 또는 App Store Connect 연결 도구를 찾지 못했다. 공개 도구는 검색어 조사·추적용이며 App Store 소개문을 게시하는 도구로 확인되지 않는다. native Mac 순위 지원, 유료 요금제·계정, API 키가 먼저 필요하다. [조사 근거](research.md#applyra-mcp-존재-확인과-mac-지원-한계).

Mac 지원을 확인하고 연동할 때에는 공급자가 반환한 플랫폼·국가·점수 정의부터 검증한다. API 키를 채팅·Git·주간 실행 프롬프트에 넣지 않는다. 이번 작업은 계정 생성·결제·키 발급·MCP 설치·예약 작업·스토어 게시를 수행하지 않았다.

## 검증 기록

문구 형식 검사에서 이름 18/30자, 부제 22/30자, 키워드 UTF-8 65/100바이트를 확인했다. 제출 준비 검사는 앱 ID·공개 URL·배포 검증이 없어 정상적으로 미완료를 반환한다.

합성 CSV로 정상 전환율 계산, 누락값·0분모 구분, iOS 자료 혼입·음수·잘못된 기간 거부를 확인했다. 34개 한글 문자(102바이트)가 키워드 제한에서 거부되는 것도 확인했다. 실제 검색 순위나 설치 실적을 검증한 결과는 아니다. 앱 실행 파일을 수정하거나 다시 설치하지 않았다.
